# 懸賞キャンペーン応募支援ダッシュボード

X、Instagram、TikTok、公式サイトなどのプレゼントキャンペーンや懸賞キャンペーンを整理し、人間が手動応募しやすくするためのローカルWebアプリです。

キャンペーン本文、応募条件、締切、リスク、コメント案、応募履歴、応募後フォローをブラウザ内で管理できます。バックエンドや外部APIは不要で、データはブラウザの localStorage に保存します。

## 重要な注意

このアプリはSNS自動応募Botではありません。

以下の機能は実装していません。

- X / Instagram などへの自動ログイン
- 自動フォロー
- 自動リポスト
- 自動いいね
- 自動コメント
- 自動DM
- 自動投稿
- SNS APIによる自動応募
- CAPTCHA回避
- レート制限回避
- アカウント凍結回避
- ブラウザ自動操作によるSNS応募

投稿URLを新しいタブで開くことはできますが、応募操作は必ずユーザー自身が手動で行う設計です。

## 主な機能

- キャンペーン登録
- キャンペーン本文の解析補助
- リスク判定
- 応募優先度スコア
- コメント案生成

## 使い方

このアプリは通常のHTML + CSS + JavaScriptで動きます。ビルドは不要です。

### ローカルサーバーを起動する

プロジェクトフォルダで以下を実行します。

```bash
python3 -m http.server 4173
```

### 通常画面を開く

ブラウザで以下を開きます。

```text
http://localhost:4173/
```

### テスト画面を開く

```text
http://localhost:4173/tests.html
```

テスト画面で「テスト実行」ボタンを押すと、主要ロジックの自動テストを実行できます。

## 基本操作

### サンプルデータ投入

「バックアップ」タブから「サンプルデータ投入」を押します。低リスク、要確認、応募非推奨、コメント必須、締切間近などの架空キャンペーンが追加されます。

### 新規登録

「新規登録」タブでキャンペーン名、主催者、SNS種別、投稿URL、本文、賞品、締切、応募条件などを入力します。

本文を貼り付けて「本文から推定入力」を押すと、賞品、当選人数、締切、応募条件、当選連絡方法などをキーワードベースで補助入力します。

### 応募済みにする

一覧や今日やることのカードから「応募済みにする」を押します。

- ステータスが「応募済み」になります。
- 応募日が空の場合、今日の日付が入ります。
- 結果ステータスが未確認の場合、「連絡待ち」になります。

応募そのものはSNSや外部サイト上で手動で行ってください。

### 応募履歴を編集する

「詳細・編集」タブの「応募履歴」セクションで、応募日、結果ステータス、確認予定日、発送日、受取日、応募後メモなどを編集できます。

「応募履歴」タブでは、応募済み案件や当選・落選結果を一覧で確認できます。

### バックアップ

「バックアップ」タブからJSONエクスポートを行ってください。別ブラウザや別端末へ移す場合は、JSONインポートで復元します。

CSVエクスポートはExcelやGoogleスプレッドシートで開きやすいよう、BOM付きUTF-8とCRLFで出力します。

## データ保存

- 保存先: ブラウザの localStorage
- localStorageキー: `kensho_campaign_dashboard_v1`
- バックエンド、外部DB、外部APIは使っていません。
- ブラウザや端末を変えるとデータは共有されません。
- GitHub Pagesに公開しても、データはクラウド同期されません。
- Macで登録したデータはスマホには自動同期されません。
- スマホで登録したデータはMacには自動同期されません。
- 端末間で移す場合はJSONエクスポート / インポートを使ってください。
- ブラウザのデータ削除、プライベートブラウズ、別プロファイル利用でデータが消える場合があります。
- ブラウザのキャッシュ削除やサイトデータ削除でデータが消える可能性があります。
- 定期的なJSONエクスポートを推奨します。

## GitHub Pages公開手順

このアプリはビルド不要の静的サイトです。`index.html` がリポジトリのルートにあり、CSSとJavaScriptは相対パスで読み込むため、GitHub Pagesでそのまま公開できます。

1. GitHubで新しいリポジトリを作成します。
2. ローカルリポジトリにremoteを追加します。
3. `main` ブランチへpushします。
4. GitHubのリポジトリ画面で `Settings` → `Pages` を開きます。
5. `Source` を `Deploy from a branch` に設定します。
6. `Branch` を `main`、folderを `/root` に設定します。
7. 表示された公開URLにアクセスします。

コマンド例:

```bash
git remote add origin https://github.com/ユーザー名/リポジトリ名.git
git branch -M main
git push -u origin main
```

公開後のURL例:

```text
https://ユーザー名.github.io/リポジトリ名/
```

テスト画面:

```text
https://ユーザー名.github.io/リポジトリ名/tests.html
```

### GitHub Pages公開後の注意

GitHub PagesはHTML、CSS、JavaScriptを配信するだけです。キャンペーンデータはGitHub上には保存されず、各ブラウザの localStorage に保存されます。

- PCとスマホのデータは自動同期されません。
- ブラウザごと、端末ごとに別データになります。
- 端末移行や共有にはJSONエクスポート / インポートを使ってください。
- 重要なデータは定期的にJSONバックアップを取ってください。

詳しい公開手順は [docs/DEPLOY.md](docs/DEPLOY.md)、バックアップ手順は [docs/BACKUP.md](docs/BACKUP.md) を参照してください。

## テスト方法

1. ローカルサーバーを起動します。
2. `http://localhost:4173/tests.html` を開きます。
3. 「テスト実行」ボタンを押します。
4. 全テスト件数、成功件数、失敗件数、詳細ログを確認します。

テストは本番localStorageデータを退避・復元する設計です。

## 安全設計

- SNS自動操作は実装していません。
- 投稿URLは新しいタブで開くだけです。
- 応募操作は人間が手動で行います。
- `javascript:` URLは拒否します。
- `http://` / `https://` 以外のURLは拒否します。
- JSONインポート時に配列形式、URL、日付、タグ、ステータスなどを検証します。
- localStorageデータが破損していても、空配列で復旧します。
- CSVはBOM付きUTF-8で出力し、日本語文字化けを抑えます。
